# PX4 Cascade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `Px4Cascade`, the PX4 multicopter cascade for the Hummingbird, and fly homing on its velocity tier.

**Architecture:** Pure functions in `px4_math.py` are the firmware blocks (constrain, tilt, thrust, attitude, rate). `Px4Cascade` converts the simulator state into right-handed NED/FRD, runs the tier the companion asked for, and mixes Newton-metres back through the same rotor map as `SE3Control`. The homing runner swaps that controller in and converts the guidance command into PX4 NED before `update`.

**Tech Stack:** Python >= 3.8, NumPy, SciPy `Rotation`, pytest. Firmware source of the equations: HummingbirdTeam/Firmware `795b31a5c7`.

**Spec:** `docs/superpowers/specs/2026-10-24-px4-cascade-design.md`

## Review Focus

- A velocity command of 19 m/s, including straight down, is not clipped. The position tier still clamps horizontal speed to 12 m/s and down speed to 1 m/s. Tested in Task 14.
- An omitted yaw holds the current NED yaw. A level FLU identity is NED yaw `pi/2`, and treating the omission as yaw 0 yaws the hover. Tested in Task 11.
- A flat output with no `tier` is the position tier in the simulator frame. `FRD_NED` does not run the ENU map. Tested in Task 17.
- Rate saturation flags come from the previous mix and are expressed in FRD, so a FLU pitch stop does not keep integrating pitch. The first step is unsaturated. Tested in Task 16.
- Homing `(n, e, d)` and yaw become PX4 `(e, n, d)` and `pi/2 - yaw`, so the no-lock cruise starts with no horizontal velocity error. Tested in Task 18.

### Task 16: Rate-tier saturation flags

**Files:**
- Modify: `rotorpy/controllers/px4_cascade.py`
- Modify: `tests/test_px4_cascade.py`

**Interfaces:**
- Consumes: `rate_torque` and the motor mix
- Produces: `tier == "rate"`. Required keys `rate_frd` and `thrust`. The rate loop's setpoint is `rate_frd`. `thrust_magnitude` is the companion `thrust`. No attitude loop.

Saturation flags for the next rate step are the signs of `commanded_moment - achieved_moment` after the thrust clamp. Achieved moment is `(f_to_TM @ clamped_thrusts)[1:4]` in the active body frame. Map that residual through `flu_to_frd` when the frame is FLU-ENU, then take the sign, so the flags line up with FRD rate error. A residual with absolute value at or below `1e-6` N·m is unsaturated. The flags start cleared, so the first step integrates and the second moment moves. The third moment stays put.

- [ ] **Step 1: Write the failing test**
